# YaalTrail – Design Facts (as implemented)

Reference for drawing UML diagrams (class, ER, component, sequence). Everything here is taken from the code at commit `788a3cd`, plus these uncommitted changes in the working tree:
- the photo feature (FR-11, FR-45);
- the `tests/YaalTrail.Tests` project.

It describes what the code does now, not what the SRS asks for.

Stack: ASP.NET Core 8 Web API (C#), EF Core 8.0.11 with Npgsql (PostgreSQL), Supabase Storage for photo files (REST API via HttpClient), static HTML/CSS/JS front end in `YaalTrail.Api/wwwroot`, Leaflet 1.9.4 from a CDN.

Rules that look like constraints but are **not** enforced by the database:
- At most one OpeningHour per (PlaceId, DayOfWeek): only `AdminPlaceService` checks this. There is no unique index.
- Category names are unique, ignoring case: only `AdminCategoryService` checks this. There is no unique index.
- At most 5 PlaceImages per place, numbered 0, 1, 2, …: only `AdminPlaceImageService` keeps this. There is no check constraint.
- When a place is deleted, the database removes its PlaceImage rows (Cascade), but the files stay in the Supabase bucket. Only the single-photo delete endpoint removes a file.

### 2.4 Seed data (`Data/DbSeeder.cs`, run at start-up by `Program.cs`)
- `SeedPlacesAsync`: runs only when the Categories table is empty. It adds 6 categories (Religious, Heritage, Natural, Recreational, Dining, Public) and 17 published places. Each place gets 7 OpeningHour rows; a day listed in `ClosedOn` is stored with `IsClosedAllDay = true` and no times. No images are seeded; photos are added through the admin photo endpoints.
- `SeedAdminAsync`: adds `admin@yaaltrail.local` (DisplayName "Administrator") if that account doesn't exist yet. The password is hashed from user-secret `Admin:InitialPassword`; if the secret isn't set, nothing is added.

### 2.5 External photo storage (Supabase Storage)
- **Bucket:** `place-photos` (the default of `SupabaseOptions.Bucket`). It is a **public** bucket, so visitors' browsers load photo files straight from Supabase, not through the API.
- **Object names:** `Guid.NewGuid().ToString("N") + extension` (`.jpg`, `.png` or `.webp`). Nothing from the original file name is used.
- **Public URL stored in `PlaceImages.ImageUrl`:** `{Supabase:Url}/storage/v1/object/public/{bucket}/{objectName}`.

### 3.1 SupabasePhotoStorage (how it calls Supabase Storage)
- `BaseUrl = Supabase:Url` without a trailing "/". `PublicPrefix = {BaseUrl}/storage/v1/object/public/{Bucket}/`.
- **Every request** sends `Authorization: Bearer {ServiceKey}` and `apikey: {ServiceKey}`. The target is `{BaseUrl}/storage/v1/object/{Bucket}/{objectName}` (objectName URL-escaped).
- **UploadAsync:**
  1. `EnsureConfigured()`: if Url or ServiceKey is empty → `PhotoStorageException("Photo storage is not configured …")`.
  2. objectName = GUID ("N" format) + `type.Extension`.
  3. **POST** with a `ByteArrayContent` body, `Content-Type: {type.ContentType}` and `x-upsert: false`.
  4. Non-success status → logs a warning with the status code only → `PhotoStorageException("The photo could not be saved to storage. Please try again.")`.
  5. Success → returns `PublicPrefix + objectName`.
- **DeleteAsync:**
  1. `EnsureConfigured()`.
  2. If the URL does not start with `PublicPrefix`, it returns without doing anything (only files in its own bucket are deleted).
  3. Otherwise **DELETE** the object; a non-success status → warning (status code only) → `PhotoStorageException`.
- **Network errors** (`HttpRequestException`, `TaskCanceledException`) → warning with the exception type name only → `PhotoStorageException("Photo storage could not be reached …")`.
- The service key is never logged, and `RedactLoggedHeaders(_ => true)` in Program.cs redacts every header value in HttpClient logs (NFR-15).

#### 4.2.1 AdminPlaceImagesController (FR-11, FR-45)
Class attributes: `[ApiController]`, `[Route("api/admin/places/{id:int}/images")]`, `[Authorize(Roles = "Admin")]`. Its only dependency is `IAdminPlaceImageService`.

| Endpoint | Status codes |
|---|---|
| **POST** `…/images`. Attributes: `[Consumes("multipart/form-data")]`, `[RequestSizeLimit(3 MB + 64 KB)]`, `[RequestFormLimits(MultipartBodyLengthLimit = 3 MB + 64 KB)]`. It opens `form.File.OpenReadStream()` and calls `AddAsync(id, stream, form.File.Length, form.Caption, AdminId)`. | **201** with `AdminPlaceImageDto` in the body (no Location header) · **400** ValidationProblemDetails (no `file`, or caption over 200) · **400** `ProblemDetails("Invalid photo", message)` from `AdminRequestException` · **401** / **403** · **404** place not found · **415** body is not multipart/form-data (the `[Consumes]` check runs before authorization) · **502** `ProblemDetails("Photo storage error", message)` from `PhotoStorageException` · a body over the size limit is rejected by ASP.NET Core before the service runs |
| **PUT** `…/images/order` → `ReorderAsync(id, imageIds, AdminId)` | **200** `List<AdminPlaceImageDto>` in the new order · **400** `ProblemDetails("Invalid photo", …)` if the ids aren't exactly this place's photos · **400** validation if the body isn't a JSON array of ints · **401** / **403** · **404** place not found |
| **DELETE** `…/images/{imageId}` → `DeleteAsync(id, imageId, AdminId)` | **204** · **401** / **403** · **404** place not found, or the photo doesn't belong to this place. A storage failure while removing the file does **not** change the status (best effort) |

## 5. Call flows (for sequence diagrams)

Participants used below:
- **Visitor side:** Browser (app.js and modules) → Controller → Service → AppDbContext/PostgreSQL.
- **Admin side:** Browser (admin.js and modules) → JwtBearer middleware / AdminSessionStore → Controller → Service → AppDbContext.
- **Photo flows** add **IPhotoStorage (SupabasePhotoStorage)** → **Supabase Storage REST API**.

### 5.1 Visitor loads the catalogue
1. The browser loads `index.html`, which loads Leaflet and `js/app.js` (ES module).
2. When `app.js` loads, it builds the plan store with `createPlanStore`. The store restores the saved plan from localStorage (try/catch). `app.js` then creates the plan panel with `createPlanPanel` and calls `init()`.
3. `init()`:
   1. `wireEvents()`.
   2. `watchHeaderHeight()` (ResizeObserver → CSS `--header-height`).
   3. `onPlanChanged()`: updates the badge, syncs the toggle buttons, and calls `planPanel.refresh()` (see 5.3).
   4. In parallel:
      - `loadCategories()` → `api.getCategories()` → **GET `api/categories`**
      - `loadSettings()` → `api.getPlannerSettings()` → **GET `api/settings/planner`**
   5. Then `loadPlaces()` → `api.getPlaces({categoryIds, search, sort})` → **GET `api/places?sort=distance`**. The `categories` and `search` parameters are added only when set.
4. **GET `api/categories`** → `CategoriesController.GetCategories` → `CategoryService.GetAllAsync`:
   1. `CatalogueCache.GetOrLoadAsync("catalogue:categories")`.
   2. On a cache miss, one SQL query: all categories ordered by Name, projected to CategoryDto. The result is cached for 60 s.
   3. Returns a copy of the list.
5. **GET `api/places`** → `PlacesController.GetPlaces` → `PlaceService.GetPlacesAsync`:
   1. `GetPublishedPlacesAsync()` → `CatalogueCache.GetOrLoadAsync("catalogue:published-places")`. On a miss there is one SQL query: `Places WHERE IsPublished`, projected to a private `PlaceSummary` record. The category name comes from a JOIN and the first photo's URL from a sub-query ordered by SortOrder. The result is cached for 60 s.
   2. Category filter, in memory: `ParseIds("1,2")` ignores anything that isn't a number.
   3. Search, in memory: the trimmed term is matched case-insensitively against Name or Description.
   4. Sort: `sort=name` → by name (OrdinalIgnoreCase). Otherwise → by DistanceKm, then by name.
   5. Each row becomes a `PlaceListItemDto`; `EntryFeeText` is "Free entry" or "LKR 1,500".
   6. Returns `PlaceListResponseDto(Count, Items)`.
6. Browser:
   - `renderResultCount`, then `renderPlaceList`: a card button per place, plus a plan toggle button.
   - On a card, `createCardPhoto` shows `photoUrl` as a decorative `<img alt="">` (the card text already names the place). With no photo, or if the image fails to load (`onError`), it shows the category-letter placeholder instead (NFR-24).
   - If there are no results, `renderListMessage` shows the "no results" message (FR-06). If the request fails, it shows an error with a retry button.
   - If the map view is active, `map.setPlaces`.
   - Responses older than the latest request are ignored (`latestRequestNo`).
   - Search waits 300 ms after typing stops; chip and sort changes call `loadPlaces()` again.

### 5.2 Visitor opens place details
1. Clicking a card (or "View details" in a map popup, or a stop name in the plan) → `app.openPlace(id, trigger)`:
   1. `renderDetailLoading`.
   2. `dialog.showModal()`.
   3. `api.getPlace(id)` → **GET `api/places/{id}`**.
2. `PlacesController.GetPlace` → `PlaceService.GetPlaceAsync(id)`. This result is **not cached**, because "open now" depends on the time.
   1. One SQL query: `Places` with Include Category, Images and OpeningHours, `AsSingleQuery`, `WHERE Id = id AND IsPublished`.
   2. Not found or unpublished → null → controller returns **404**.
   3. `SriLankaTime.Now(clock)` gives today's weekday and the current time in Colombo.
   4. Today's OpeningHour row is the one for that weekday.
   5. Opening hours are ordered Monday → Sunday. Photos are ordered by SortOrder and limited to 5.
   6. Missing values become "Information not available". A closed day shows "Closed".
   7. `IsOpenNow`: there is a row for today, the day is not closed all day, both times are set, and open ≤ now < close.
   8. Returns `PlaceDetailDto` → 200.
3. Browser: `renderDetail` draws:
   - header and gallery (`createGallery`, see §7.2);
   - status badge (✓ Open now / ✕ Closed now, icon + text);
   - facts, About, Travel tips;
   - the opening-hours table with today marked;
   - the NFR-07 notice;
   - actions: the plan toggle and "View day plan".

   On error, `renderDetailError` is shown instead. Closing the dialog returns focus to the element that opened it.

### 5.3 Visitor builds a day plan (POST `api/plan/calculate`)
**Browser**
1. "Add to day plan" (card, detail or popup) → `planToggle` → `app.togglePlace(place)` → `planStore.add(place)`. Removing calls `planStore.remove(id)`.
2. Every store change calls `commit()`:
   1. `savePlan()` writes to localStorage key `yaaltrail.dayPlan.v1` (try/catch).
   2. `onPlanChanged()`: updates the badge count, `syncPlanToggles(document)`, and calls `planPanel.refresh()`.
3. Other changes also go through the store and `commit()`:
   - date input → `setPlanDate`
   - start-time input → `setStartTime`
   - visit-minutes input → `setDuration`
   - ↑/↓ or drag → `move`/`moveTo` (sets `manualOrder`)
   - "Auto-order" → `autoOrder()` (`manualOrder = null`)
   - "Clear plan" (after `confirm()`) → `clear()`
4. `planPanel.refresh()`:
   - Empty plan → shows the empty message; no request is sent.
   - Otherwise `api.calculatePlan(store.toRequest())` → **POST `api/plan/calculate`** with body `{ startTime, planDate, placeIds, manualOrder, durationOverrides }`.
   - Older responses are ignored (request number).

**Server**
5. `PlanController.Calculate` → `PlanService.CalculateAsync(request)`:
   1. `ParseStartTime`: null or empty → 08:00; otherwise exact "HH:mm", else `PlanRequestException`.
   2. `ParsePlanDate`: null or empty → today in Sri Lanka time; otherwise exact "yyyy-MM-dd", else exception.
   3. `placeIds` are made distinct.
   4. One SQL query: Places with Include Category and OpeningHours, `WHERE IsPublished AND Id IN placeIds`.
   5. Any id not found → `PlanRequestException("Unknown or unpublished place id(s): …")`.
   6. Each row becomes a `PlanPlace`; then `PlanBuilderService.Build(new PlanInput(...))`.
6. `PlanBuilderService.Build` (pure; no database):
   1. **Order:**
      - If `ManualOrder` has items, `ApplyManualOrder` is used. It must contain every place exactly once, else `PlanRequestException`.
      - Otherwise `OrderByNearestNeighbour`: sort the remaining places by Id. Start at the reference location. Repeatedly pick the place with the smallest straight-line (haversine) distance from the current position; a strict `<` means ties go to the lowest id. That place becomes the current position.
   2. **Start state:** `clock` = start time in minutes since midnight. Previous position = reference. Last scheduled position = reference. Last scheduled departure = start.
   3. **For each place, in order:**
      1. `km = RoadKm(previous, place)`, i.e. haversine × RoadFactor (1.3).
      2. `travel = round(km / AverageSpeedKmh × 60)`, rounding halves away from zero.
      3. `visit` is the first of these that applies:
         - the override, which must be 1–720, else exception;
         - 90 if the category is Natural and the name contains "beach";
         - the category default: Religious 45, Heritage 60, Natural 60, Recreational 60, Dining 45, Public 30;
         - otherwise 60.
      4. `arrival = clock + travel`; `departure = arrival + visit`.
      5. `isScheduled = arrival ≤ LatestArrival (18:00)`.
      6. **Scheduled:**
         - `OpeningHoursValidator.Check(hours, planDay, arrival)` adds at most one warning: ArrivesAfterClosing, ArrivesBeforeOpening, ClosedAllDay or HoursNotRecorded.
         - The leg's km, travel and visit are added to the totals; `scheduledCount++`.
         - Last scheduled position and departure are updated.
      7. **Not scheduled:** a `NotScheduled` warning with the estimated arrival. Arrival and Departure are null, and nothing is added to the totals.
      8. A `PlanStopDto` is added (distance rounded to 1 decimal). Then `clock = departure` and previous position = this place (this also happens for unscheduled stops).
   4. **Return leg:**
      - `RoadKm(last scheduled position → reference)` and its travel time.
      - `backAtReference = last scheduled departure + return travel`.
      - These are added to the totals.
   5. **Totals:**
      - distance rounded to 1 decimal, travel minutes, visit minutes;
      - `elapsed = backAtReference − start`;
      - `EndTime`;
      - scheduled and unscheduled counts.
   6. **Advisory:** if the number of places is greater than `MaxRecommendedPlaces` (6), an advisory text; otherwise null.
   7. Times are "HH:mm"; 24:00 or later gets the suffix " (next day)".
   8. Returns `PlanResponseDto`.
7. Controller → 200. A `PlanRequestException` → 400 ProblemDetails "Invalid plan request". Nothing is stored on the server.

**Browser**
8. `renderResult` draws:
   - the day line;
   - the advisory notice (if any) and the unscheduled notice (if any);
   - the order bar (+ "Auto-order" when the order is manual);
   - "What do these warnings mean?" (if there are warnings);
   - the stops: times or "Not scheduled", travel line, visit-minutes input, warnings (icon + label + text + hint), ↑/↓/Remove;
   - the return leg and the totals.

   On error, `renderError` shows the server's text. If the server reports unpublished ids, it offers "Remove unavailable places".

### 5.4 Admin login (with lockout and session tracking)
**Browser**
1. `admin.html` loads `js/admin/admin.js`.
2. `loadSession()` reads sessionStorage `yaaltrail.admin.session`.
   - If a stored session is expired or idle (`sessionEndReason`), it is cleared and the login screen shows why.
   - Otherwise `startSession()` runs and the current `#/…` screen is shown.
3. Login form submit → `onLogin`:
   1. Client check: email and password are non-empty and the email field is valid.
   2. `adminApi.login(email, password)` → **POST `api/admin/login`** (no Authorization header).

**Server**
4. Model validation (`[Required, EmailAddress, MaxLength(256)] Email`, `[Required, MaxLength(200)] Password`) → 400 if it fails.
5. `AdminAuthController.Login` → `AdminAuthService.LoginAsync`:
   1. `now` = UTC from TimeProvider. The email is trimmed and lower-cased.
   2. One query: `AdminUsers WHERE lower(Email) = email`.
   3. **Unknown email:** run `Verify` against a dummy hash, so the time taken is the same (the dummy hash is created once and kept in a static field). Log a warning and return null.
   4. **Locked** (`LockedUntil > now`): run `Verify` anyway (same timing). Log and return null. The counter does not change.
   5. **Wrong password:**
      - `FailedAttempts++`.
      - If it reaches 5: `LockedUntil = now + 15 min` and `FailedAttempts = 0`, and the lockout is logged.
      - `SaveChanges`; return null.
   6. **Correct password:**
      1. `FailedAttempts = 0`, `LockedUntil = null`, `LastLoginAt = now`; `SaveChanges`.
      2. `jti = new Guid ("N" format)`; `expiresAt = now + 60 min`.
      3. `CreateToken`: JsonWebTokenHandler, HS256 with the `Jwt:Key`. Claims: `sub` = admin id, `jti`, `email`, `name`, `role` = "Admin". Also issuer, audience, iat, nbf and exp.
      4. `AdminSessionStore.Start(jti, expiresAt)`. This first removes finished sessions, then stores `{ExpiresAt, LastActivity = now}`.
      5. Returns `AdminLoginResponseDto(token, "Bearer", expiresAt, DisplayName)`.
6. Controller:
   - null → **401** `ProblemDetails("Sign-in failed", "Invalid email or password.")`. The text is the same in all three failure cases.
   - Otherwise **200**.
7. **Every later admin request:**
   1. The JwtBearer middleware validates signature (HS256 only), issuer, audience and lifetime (ClockSkew 0).
   2. Then the `OnTokenValidated` event calls `AdminSessionStore.TryTouch(jti)`. It returns false if the jti is unknown (signed out or server restarted), if the token has expired, or if there has been no activity for more than 30 minutes; in the last two cases the session is also removed. Otherwise it updates LastActivity and returns true.
   3. false → `context.Fail` → **401**.
   4. Then `[Authorize(Roles = "Admin")]` checks the role (403 if it is missing).
8. **Logout:** **POST `api/admin/logout`** (authorized) → `AdminAuthService.Logout(jti)` → `AdminSessionStore.End(jti)` → 204.

**Browser after login**
9. The session is saved: `{ token, displayName, email (as typed), expiresAt (ms), lastActivity }`.
10. `startIdleWatch` (session.js):
    - pointerdown, keydown, wheel, touchstart and input events update `lastActivity` (saved at most every 15 s);
    - a check runs every 15 s; a warning banner appears 2 minutes before the 30-minute limit;
    - when the limit is reached, `logout()` is called and then `endSession('idle')`;
    - while the admin is active but no request has gone to the server for 10 minutes, a keep-alive **GET `api/admin/categories`** is sent.
11. Any 401 calls `onUnauthorized`, which runs `endSession('unauthorized')` and shows the login screen with the reason.

### 5.5 Admin creates a place
**Browser**
1. `#/places/new` → `showPlaceForm(container, null, ctx)` → `getCategories()` → **GET `api/admin/categories`**, then `buildForm`. For a new place, the Photos section is replaced by the message "Save the place first, then you can add photos."
2. Submit:
   1. `readForm`: numbers are parsed. Opening hours include only days that are marked closed or have at least one time.
   2. `validate()`: the client-side rules in §6.3.
   3. Errors go into a summary (with links to the fields) and next to each field.
   4. Otherwise `createPlace(request)` → **POST `api/admin/places`** with `Authorization: Bearer <token>`.

**Server**
3. JwtBearer + session check + role check (5.4, step 7). Then model validation of `AdminPlaceRequestDto` → 400 ValidationProblemDetails if it fails.
4. `AdminPlacesController.Create` reads `AdminId` from the `sub` claim → `AdminPlaceService.CreateAsync(request, adminId)`.
5. `ValidateAsync` collects **all** errors:
   1. Name must not be blank.
   2. Category must exist (query `Categories.Any(Id)`) – BR-05.
   3. `CheckRadius`: `StraightLineKm(reference, coordinates) ≤ RadiusKm`. Otherwise: "The coordinates are X km from the reference location (lat, lon); only places within 25 km may be added (FR-42, BR-01)."
   4. `ParseOpeningHours`, for each entry:
      - the day name must be a weekday name (case-insensitive, numbers rejected);
      - the same day may not appear twice;
      - closed → `IsClosedAllDay = true` and no times;
      - otherwise both times must parse as "HH:mm" or "H:mm", and close must be later than open (FR-43).
   5. Any errors → `throw AdminRequestException(errors)`.
6. Build the place:
   1. `new Place { CreatedAt = now }`.
   2. `Apply`: trims Name; empty Description/TravelTips → null.
   3. `DistanceKm` = the value given, or `EstimateRoadKm` (RoadKm from the reference, rounded to 2 decimals).
   4. Sets `IsPublished` and adds the OpeningHours.
   5. `UpdatedAt = now`; `MaintainedByAdminId = adminId` (FR-48).
7. `Places.Add`, then `SaveChanges`.
8. **`ICatalogueCache.Invalidate()`** removes both catalogue keys, so visitors see the change on their next request.
9. `GetAsync(id)`:
   - one query with Include Category, MaintainedByAdmin, Images and OpeningHours;
   - plus `CountSavedPlansAsync` (distinct VisitPlanId in PlanItems for this place);
   - result: `AdminPlaceDto`.
10. Controller:
    - **201** `CreatedAtAction(Get)`;
    - `AdminRequestException` → **400** `ProblemDetails("Invalid place", joined messages)` plus `errors[]`.

**Browser**
11. On success: `navigate('#/places', "<name> was added.")`.
12. On 400: `serverErrorList` maps `fieldErrors` (model validation) and `messages` (service) to fields. A message starting with a weekday goes to that day's row; "coordinates" goes to latitude/longitude; "category" goes to the category field. Then `showErrors`.

### 5.6 Admin deletes a place
**Browser**
1. "Delete" in the places table → `placesView.remove(place)` → `countSavedPlans(id)`, which first sends **DELETE `api/admin/places/{id}`** without `confirm`.

**Server**
2. `AdminPlacesController.Delete(id, confirm=false)` → `AdminPlaceService.DeleteAsync(id, false)`:
   1. Load the place; not found → false → **404**.
   2. Not confirmed: count the saved plans (distinct VisitPlanId in PlanItems where PlaceId = id).
   3. Throw `AdminRequestException("Deleting a place must be confirmed with ?confirm=true. " + "N saved plan(s) include this place; they will show it as unavailable." | "No saved plans use this place.")` → **400**.

**Browser**
3. It reads the count from the 400 text (regex `(\d+) saved plan`, or "No saved plans" = 0). If the text can't be read, it falls back to **GET `api/admin/places/{id}`** → `savedPlanCount`.
4. `confirmAction` opens the `<dialog>`: the title, the saved-plans sentence and "This cannot be undone." Cancel has focus first.
5. Confirmed → **DELETE `api/admin/places/{id}?confirm=true`**.

**Server**
6. `DeleteAsync(id, true)`:
   1. `Places.Remove(place)`, then `SaveChanges`.
   2. The database cascades to PlaceImages and OpeningHours (Cascade) and sets `PlanItems.PlaceId` to NULL (SetNull); the snapshot name stays. **The photo files are not removed from the Supabase bucket** in this flow.
   3. **`ICatalogueCache.Invalidate()`**.
   4. Returns true → **204**.

**Browser**
7. `showMessage("<name> was deleted.")`, then reload the list with **GET `api/admin/places`** and move focus to the heading.

### 5.7 Admin manages photos (FR-11, FR-45)
**Setup in the browser:**
- On `#/places/{id}`, `showPlaceForm` loads the place (**GET `api/admin/places/{id}`** → `AdminPlaceDto` with `images`). It appends `createPhotoEditor(place, ctx)` between the place details (created/updated/saved plans) and the place form.
- Photo actions are sent straight away; they are not part of "Save place".
- Each request below first goes through JwtBearer + session check + role check (5.4, step 7).

#### 5.7.1 Upload
**Browser**
1. The upload form is submitted → `onUpload(file, caption)` → `checkFile(file, count)`:
   - a file must be chosen;
   - the place must have fewer than 5 photos;
   - `file.type` must be image/jpeg, image/png or image/webp (or, if the type is empty, the name must end in .jpg/.jpeg/.png/.webp);
   - `file.size` must be ≤ 3 MB.

   A problem → the message is shown in the error line under the file field (`role="alert"`), and nothing is sent.
2. `adminApi.uploadPlaceImage(placeId, file, caption)` builds a `FormData` with `file` (and `caption` if not empty) → **POST `api/admin/places/{id}/images`** with `Authorization: Bearer`. No Content-Type header is set, so the browser adds the multipart boundary itself.

**Server**
3. `[Consumes]`, request-size limits and model validation of `AdminPhotoUploadForm` run first.
4. `AdminPlaceImagesController.Upload` → `AdminPlaceImageService.AddAsync(id, stream, length, caption, adminId)`:
   1. `LoadPlaceAsync`: one query, Place with Include Images. Not found → null → **404**.
   2. `Images.Count ≥ 5` → `AdminRequestException("A place can have at most 5 photos …")`.
   3. The caption is trimmed (empty → null); more than 200 characters → `AdminRequestException`.
   4. `ReadLimitedAsync(stream, length)`:
      - reported length ≤ 0 → "The file is empty.";
      - reported length > 3 MB → "The photo is larger than 3 MB …";
      - the stream is copied in 80 KB chunks and reading stops as soon as more than 3 MB has arrived ("larger than 3 MB"), whatever the reported length said;
      - 0 bytes read → "The file is empty."
   5. `ImageSignature.Detect(bytes)` → null → `AdminRequestException("Only JPEG, PNG or WebP images can be uploaded …")`.
   6. **`IPhotoStorage.UploadAsync(bytes, type)`** → `SupabasePhotoStorage` sends **POST `{Url}/storage/v1/object/place-photos/{guid}{ext}`** to Supabase and returns the public URL. Failure → `PhotoStorageException` → **502**, and no database row is written.
   7. A new `PlaceImage { ImageUrl = url, Caption, SortOrder = (highest existing SortOrder + 1, or 0 if none) }` is added to `place.Images`.
   8. `Touch(place, adminId)`: `UpdatedAt = now`, `MaintainedByAdminId = adminId` (FR-48).
   9. `SaveChanges`. **If the save throws:** `DeleteFileQuietlyAsync(url)` calls `IPhotoStorage.DeleteAsync(url)` to remove the file that was just uploaded (any `PhotoStorageException` is caught and logged), and the original exception is re-thrown (→ 500).
   10. **`ICatalogueCache.Invalidate()`**.
   11. Returns `AdminPlaceImageDto` → controller **201**.

**Browser**
5. The new photo is appended to the list, the upload form is reset, the list is re-rendered and "Photo uploaded." is shown (`role="status"`).
   - 400 / 502 → the server's message is shown under the file field (`errorMessage` shows the detail for 400 and 502).
   - 401 → back to sign-in.

#### 5.7.2 Reorder
**Browser**
1. ↑ or ↓ on a photo → `move(index, ±1)`: swap two ids in the current order → `adminApi.reorderPlaceImages(placeId, ids)` → **PUT `api/admin/places/{id}/images/order`** with a JSON array body.

**Server**
2. `AdminPlaceImagesController.Reorder` → `AdminPlaceImageService.ReorderAsync(id, imageIds, adminId)`:
   1. `LoadPlaceAsync`; not found → null → **404**.
   2. The ids must be exactly the place's photo ids: same count, no duplicates, every id belongs to this place. Otherwise `AdminRequestException("The new order must list every photo of this place exactly once.")` → **400**.
   3. `SortOrder = position` (0, 1, 2, …) for each id.
   4. `Touch(place, adminId)` → `SaveChanges` → **`ICatalogueCache.Invalidate()`**.
   5. Returns the photos ordered by SortOrder then Id → **200**.

**Browser**
3. The list is replaced with the returned order and re-rendered. Focus is put back on the same ↑/↓ button (`data-focus-key`), or on the section heading if that button is now disabled. "Photo order saved." is shown.

#### 5.7.3 Delete
**Browser**
1. "Delete" on a photo → `confirmAction` (dialog "Delete this photo?") → confirmed → `adminApi.deletePlaceImage(placeId, imageId)` → **DELETE `api/admin/places/{id}/images/{imageId}`**.

**Server**
2. `AdminPlaceImagesController.Delete` → `AdminPlaceImageService.DeleteAsync(id, imageId, adminId)`:
   1. `LoadPlaceAsync`; the place is not found, or the photo is not one of its images → false → **404**.
   2. `PlaceImages.Remove(image)`, and it is also removed from `place.Images`.
   3. The remaining photos are renumbered 0, 1, 2, … (by SortOrder then Id).
   4. `Touch(place, adminId)` → `SaveChanges` → **`ICatalogueCache.Invalidate()`**.
   5. **Best effort:** `DeleteFileQuietlyAsync(image.ImageUrl)` → `SupabasePhotoStorage.DeleteAsync` → **DELETE `{Url}/storage/v1/object/place-photos/{name}`**. A `PhotoStorageException` is caught and logged ("left behind"), and the response is still 204.
   6. Returns true → **204**.

**Browser**
3. The photo is removed from the list, the list is re-rendered, focus moves to the "Photos (n of 5)" heading, and "Photo deleted." is shown.

**Visitor effect of all three flows:** because the cache was invalidated, the next **GET `api/places`** recomputes each card's first photo, and **GET `api/places/{id}`** (never cached) returns the photos in their new order.

### 7.1 `js/admin/photoEditor.js` (FR-11, FR-45)
- **Exports:** `createPhotoEditor(place, ctx)`, `MAX_PHOTOS = 5`, `MAX_FILE_BYTES = 3 MB`.
  - `place` is the `AdminPlaceDto`; `ctx.dialog` is the confirm `<dialog>`.
  - It keeps its own copy of the photos, sorted by `sortOrder`.
- **It renders a `<section class="form-section photo-editor">` with:**
  - a heading "Photos (n of 5)" (`tabindex="-1"`, used as the focus target) and the hint text;
  - a `<ul class="photo-list">`. Each photo row has:
    - a thumbnail `<img>`, with alt = the caption or "Photo n of {place}". If the image fails to load, a text placeholder replaces it;
    - the caption, or "No caption";
    - a "Shown first" badge on the first photo;
    - ↑ / ↓ buttons (`aria-label` "Move photo n earlier/later"; disabled at the ends);
    - a Delete button.
  - a status line (`role="status"`) and an error line (`role="alert"`);
  - the upload `<form>`:
    - a file input (`accept="image/jpeg,image/png,image/webp"`);
    - an optional caption input (maxlength 200, with a hint);
    - an error line next to the file field (`role="alert"`, sets `aria-invalid`);
    - the "Upload photo" button ("Uploading…" while busy).

    At 5 photos the inputs and button are disabled and a note is shown.
- **Behaviour:**
  - `move(index, ±1)` → `reorderPlaceImages`;
  - `remove(image)` → `confirmAction` → `deletePlaceImage`;
  - `onUpload(file, caption)` → `checkFile` → `uploadPlaceImage`.

  After each change the list is re-rendered, keyboard focus is kept on the same control (`data-focus-key`), and a status message is shown. A 401 is left to `adminApi`/`admin.js` (which returns to sign-in).
- **Placement:** it is used only by `placeForm.js`, and only for an existing place. A new place shows "Save the place first, then you can add photos."

### 7.2 Visitor gallery in `js/detail.js` (FR-11, NFR-24, NFR-25)
- `createGallery(place)` uses at most `MAX_PHOTOS = 5` of `place.images`.
- **No photos** → `<div class="gallery">` with the category placeholder (from catalogue.js `createPhotoPlaceholder`).
- **Otherwise** → `<figure class="gallery">` containing:
  - a `gallery-main` frame with one `<img>`. Alt text is the caption, or "Photo of {place}". On `error`, the image is replaced by the placeholder;
  - a `<figcaption>`, shown only when the photo has a caption;
  - **only if there are 2–5 photos:** a `gallery-strip` (`role="group"`, `aria-label` "Photos of {place}") of thumbnail `<button>`s.
    - Each thumbnail button has the `aria-label` "Show photo n of total: {caption or Photo of place}" and contains an `<img alt="">`. If a thumbnail fails to load, it shows its number instead.
    - The photo on show has `aria-current="true"`; CSS gives it a thicker border **and** a ✓, so it is not marked by colour alone.
    - Keyboard: Tab between thumbnails, Enter/Space to show one; ArrowLeft/ArrowRight (wrapping) and Home/End move to a thumbnail and show that photo.
- **Catalogue cards** (`catalogue.js createCardPhoto`): the first photo (`photoUrl`), or the placeholder if there is none or it fails to load.
